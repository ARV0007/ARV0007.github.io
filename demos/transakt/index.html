Try Transakt

Six requests against the live API: wake it, sign up, take a payment, send it again by accident, read the ledger, then try a forged key. Each step shows the exact request and what came back.

This creates a real merchant and a pretend payment in Transakt's database. The page makes up the name, email and password; nothing about you is sent. The bank is simulated and declines about 1 payment in 10, like a real one sometimes would.

The browser couldn't reach the API. It runs on a free plan and may still be starting, or redeploying. Wait a minute and press the button again.

You can always run the same steps from a terminal; the commands are in the README.

  1. Wake the server

    Free hosting puts the API to sleep when nobody uses it. The first request can take up to a minute; after that it's quick.

  2. Sign up as a merchant

    The answer includes your API key. It's shown this once and stored only as a hash, so not even the database can show it again.

  3. Take a payment

    Amounts travel as whole paise, never as decimals, so ₹500 is 50000. The request carries an Idempotency-Key: a name for this one attempt.

  4. Send it again, as a retry would

    A phone loses signal and the app resends. Same request, same Idempotency-Key. A gateway without protection would charge twice.

  5. Read the ledger

    Every captured payment writes two entries that must cancel out: money in at the gateway, money owed to you. Entries are only ever added, never edited.

  6. Try a forged key

    Keep the first 8 characters of your key, which is how Transakt looks it up, and change the rest. The lookup finds you; the hash check still refuses.

How it works: design notes. The API only lets this one site call it from a browser; curl works from anywhere.
