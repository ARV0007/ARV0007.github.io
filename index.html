Transakt

A payment gateway, built from scratch in Spring Boot

Merchants sign up, get an API key and create payments. The hard parts are the ones you only notice when they go wrong: a retried request must not charge twice, money must never be a float, and an event must reach the merchant even if Kafka was down when the payment settled.

Try it in your browser Code Design notes
  • Idempotency keys enforced by a PostgreSQL unique constraint, so concurrent retries return the same payment.
  • Money kept as integer paise in an append-only double-entry ledger.
  • Transactional outbox to Kafka, then webhooks with retries and a dead-letter topic.
  • Hashed API keys or JWTs, per-merchant rate limits, Redis-cached key lookups that fall back to Postgres.

Java, Spring Boot, Spring Security, PostgreSQL, Redis, Kafka, Flyway, GitHub Actions, Render

Sentinel

Fraud investigation for Transakt, with a person making the call

Three Python services sit beside Transakt without changing a line of it. A small ML model scores every settled payment in about a millisecond. The few it flags go to a LangGraph agent, whose specialists gather evidence through read-only MCP tools and recommend an action. An analyst decides, and that decision becomes training data.

Watch the replay Code
  • Graded against planted, labelled fraud: 6 of 6 incidents with a case, 0 cases on honest merchants.
  • Only 3–4% of payments reach the agent; the rest never touch an LLM.
  • Every number in a written recommendation is checked against the evidence before it is shown.
  • Batched Kafka polls took Redis-backed scoring from 355 to 3,505 payments a second.

Python, FastAPI, LangGraph, MCP, A2A, scikit-learn, Kafka, Redis, Prometheus, Grafana

ForgeFlow

An AI app builder in Java, in the spirit of Lovable

Describe an app or paste a screenshot and get a running app back, then keep changing it by conversation. The agent isn't allowed to finish until its code passes a build; if it fails, the errors go back to the agent to fix. A reviewer agent reads the diff and can send work back.

  • 290 tests against real Postgres, Redis, Qdrant and S3 on every push.

Open source

Two fixes to libraries a lot of Java code depends on. Both are open pull requests under review.

Mockito #3859

Fixes issue #345, open since 2016

Verifying with after() polled in a loop, and every poll captured the same arguments again, so a captor could fill with millions of copies. The fix waits for an invocation instead of polling and captures each one once. The project's lead maintainer suggested that direction in review.

Apache Kafka #23926

Fixes KAFKA-9998

After a forced close, the producer joined its I/O thread with no timeout, so a callback that blocked that thread made close(timeout) hang. The wait is now capped at max.block.ms with a warning, and Thread.join(0), which means "wait forever", is no longer called when time has run out.
